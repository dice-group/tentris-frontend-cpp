# Tᴇɴᴛʀɪs fontend

This provides an HTTP frontend for the [Tᴇɴᴛʀɪs](https://github.com/dice-group/tentris-lib) library.

## Routes
Tᴇɴᴛʀɪs provides four routes.
1. `/sparql` this is the default route to submit read queries like `SELECT`, `ASK`, `CONSTRUCT`, etc.
2. `/stream` accepts the same queries as `/sparql` but streams the response back to the requester.
   It is thus optimized for large responses.
3. `/update` this is the default route to submit write queries like `DELETE WHERE`, `INSERT DATA`, etc. .
   Note: at the moment only single updates are supported because multiple updates cannot yet be applied atomically.
4. `/update_data` a specialized version of `/update`. It only accepts single `INSERT DATA` and `DELETE DATA` updates
   and uses a faster parser to digest those updates faster than the `/update` route.

If `--credentials <CREDS>` is specified all routes are subject to authentication. The first two routes require the read-only user
and the latter two routes require the read-write user.


## Log Verbosity
By default Tᴇɴᴛʀɪs will only log messages with log-level `INFO` and above. If you want more verbose logging output
use the `RUST_LOG` environment variable.

### Examples
- `RUST_LOG=debug`: Logs everything down to `DEBUG`. This will display more than what is generated by the frontend. For instance, this also displays `DEBUG` messages from the request handling.
- `RUST_LOG="tentris=debug"`: Logs down to `DEBUG` but only the messages specifically generated by the frontend.
- `RUST_LOG="tower_http=debug,tentris=debug"`: Logs `DEBUG` messages from the frontend and from the middleware.

See [tracing-subscriber docs](https://docs.rs/tracing-subscriber/0.3.17/tracing_subscriber/filter/struct.EnvFilter.html) for more info


## Production Build

You should use the [Dockerfile](./Dockerfile) to build tentris-frontend. It is based on alpine linux to provide fully
statically linked executables based on musl instead of glibc. Linking fully statically is broken with glibc.

Steps:

1. Make sure to provide credentials for https://conan.dice-research.org/artifactory/api/conan/tentris-private
    via the `CONAN_USER` and `CONAN_USER` build arguments.
2. Have an `ssh-agent` instance with your github ssh private key running. If it isn't already running, run:
    ```bash
    eval $(ssh-agent)
    ssh-add
    ```

3. Build the executable:
    ```bash
    ./package.sh YOUR_CONAN_USER YOUR_CONAN_PW
    ```

## Development

Additionally required tools:
- clang >=14 or gcc >=12
- libstdc++(gcc) >=12
- CMake >=3.21
- conan >=1.59,<2.0

You must have [tentris](https://conan.dice-research.org/artifactory/api/conan/tentris)
and [tentris-private](https://conan.dice-research.org/artifactory/api/conan/tentris-private) in your conan remotes.
tentris-private requires credentials to be accessed.

```bash
cargo build # or cargo build --release
```
